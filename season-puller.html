SEASON PULLER

// reads every track in every seasonal playlist and builds the song database

Sign in with Spotify. This uses the site's own Spotify app and keeps a refresh token, so it renews itself mid-run.

That matters here: Spotify removed its bulk-metadata endpoints in February 2026, so genres are read one artist at a time — roughly 1,200 requests on top of the playlists. A full pull can outlast the ~1 hour lifetime of a hand-generated token, which is what makes those fail halfway with token expired or invalid.

This is a credential for your Spotify account. Paste it into db/spotify_tokens.sql's seed statement, or set it as SPOTIFY_REFRESH_TOKEN. Spotify replaces it on first use, so the widget needs the store to keep working.

or paste a token by hand

From the current user's playlists endpoint → Try it, authorized with playlist-read-private. It must be a user token; a client-credentials token has no access to /me and returns 401. These expire in about an hour and cannot refresh, so long runs may not finish.

A full pull can take a few minutes for the complete archive. Genres come from each track's primary artist.

Uses GetSongBPM via /api/song-bpm, so it needs GETSONGBPM_API_KEY set on the deployment. Adds a few minutes; unmatched tracks are simply left blank.

When Spotify emails your export:
  1. Drop the zip below — or unzip it and drop the Streaming_History_*.json files.

  3. Download the generated CSVs and commit them under /seasons/.

This is the one source with your full history — the API only ever returns your last 50 plays. The smaller account data export works too, it just carries less per play.
